This is a disposable standalone Godot fixture, not a production save design or an edit to Havenline. No scene, character, save migration, existing save path or literal save filename is used. The earlier coordinator/timing fixture is unchanged and is not joined to this scenario. The only effects collected here are cue signals for legitimate new commits, never rendered animation. Amounts, absolute capacities, material tokens and receiver names are deliberately fixture-only.

The trusted typed planner is copied byte-identically from the earlier staged candidate, hash `0ae04e267c01a0163cc29f6eabb23c1d8cc93edb635ced9e865a5452dcde9151`.

Run `./run.sh /path/to/existing/shared/godot/test/lock`. Takes the nonblocking exclusive Godot lease; refuses a competing native process; prepares a new isolated project, HOME/XDG/TMP and two new private, single-component, explicitly marked temporary profiles. Each of two scenarios launches a real Godot writer, waits for its own PID-reported readiness after the chosen cut, then sends SIGKILL to that exact child and waits for status 137 before separately launching a different Godot reader PID. Independent shell hashes across each kill match the writer/reader byte checks; stage before the first cut is byte-identical to the first promoted primary in the other cut. Owned temporary profiles are cleaned on exit.

- After stage readback, before promotion: the old primary survives unchanged, an exact orphan pending stage remains, and opening projects old state without promoting, modifying, deleting, or publishing a cue. A legal retry commits one 52-unit debit and credit and produces one cue; mutated duplicate causes no state or cue change.
- After promotion, before in-process publication: exact new primary survives, no stage remains, and opening projects exactly one 52-unit debit and credit with **zero** recovery cue. Original and mutated duplicate requests do not reapply or emit. With 52 synthetic units deliberately still available, a fresh equivalent ticket is accepted once and alone produces its new cue. Losing the original transient cue is intentional under the tested oracle semantics.
- Both cases preserve row order and the untouched row quantity and match exact expected typed ledger bytes. `runtime.log`: 36/36 Godot assertions plus shell process, files and digest checks, Godot 4.7.2, four sequential unique process runs. This is process-loss recovery on the same running OS and filesystem at two known cuts only. No power loss or filesystem durability (including fsync of the containing directory), interruption inside rename, concurrent writers, trust against malicious local processes, production schema/capacity, real input, animation, or gameplay integration is established.
