# Detached coordinator-owned transfer presentation, successor v2

**Test-only, no production gate, no images.** Separate native Godot project. Starts from the prior exact presentation-volume fixture manifest SHA-256 `1217b23b7f17a386f1f7a0b81b3772b8d5c025ee2974defb017b668637e0fb34`; that fixture explicitly trusted the caller's receipt/sequence. Independent negative control reported that a caller supplying a made-up fresh cue, matching receipt and greater sequence could make the old standalone presenter animate after completion. That remains true of the unchanged v1; this successor does not expose an `admit` or receipt import method.

The single coordinator owns the fixture ledger, typed policy, committed sequence, epoch and pending presentations. Only exact four-field intents enter the write path. An allowed intent is checked through the byte-identical existing staged typed planner (`planner_upstream.gd`, SHA-256 `0ae04e267c01a0163cc29f6eabb23c1d8cc93edb635ced9e865a5452dcde9151`). The next typed ledger and receipt are set before any queued visual or scene-node callback; trusted epoch and sequence are locally created, never supplied as proof by a caller. The animation clocks are ticket/epoch-addressed and can't change accounting. The published observation snapshot is deeply copied. Plain Node3D flight points have no presenter script or callable cue-import method. Forged proof fields, a mutated snapshot, an uncommitted clock, stale epoch/ticket, duplicates and wrong row/receiver are rejected through the intended interfaces. A valid fresh typed intent is still allowed within the fixture rules; this is not player identity, authenticated command ingress, or exploit prevention. GDScript underscore names are conventions, not a sandbox against arbitrary injected scripts or native tampering.

Active visuals serialize; another valid intent commits before queueing. Reattach may intentionally abandon in-flight/queued transient effects, retaining committed receipts. Reentrant arrived or scene-node callbacks cannot create another commit or advance the visual during a commit presentation. Canceling during dispatch suppresses remaining old signals; queued completion opens the next exact committed entry, and each uninterrupted presentation emits one completion after its last actual positional endpoint. None of this introduces money, fees, scene integration or mutable visuals for the other row.
