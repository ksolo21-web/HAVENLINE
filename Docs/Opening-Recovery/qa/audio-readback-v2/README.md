## V2: generated peak reconciliation

V1 seal 509ad45900e2f1763f8429053853034b8251274515a7a5042f016a39bf478b93 is preserved. The archived generator sets gain to min(2.4, .72/max(peak,1e-9)), exports the floating peak times gain, and writes each signed sample as int(clamp(sample*gain,−.98,.98)*32767), truncating toward zero. The .98 clipping limit is not the signal maximum when the gain cap is respected. V2 requires a finite positive JSON float no more than 0.72 plus two ULPs at that value (2.22×10⁻¹⁶). It scans all actual signed little-endian int16 samples for max(abs(sample)), including the negative extreme. If x = manifest peak × 32767, accepted PCM integer must be between trunc(max(0, x−4 ULP(x))) and trunc(x+4 ULP(x)), inclusive. This admits adjacent counts only within a few binary64 rounding units of an integer boundary, not a full-count tolerance elsewhere. Sub-LSB nonzero peak may arithmetically quantize to zero in synthetic controls; exact zero metadata is rejected for this known generator. This binds a quantized peak interval to the bytes; it does not authenticate every decimal digit within one quantization cell, supplied external provenance, sound semantics or listening quality. Positive controls include a negative dominant sample and near-boundary reconciliation; tampered .98, a legal-range incorrect peak, and a value deliberately outside the boundary window are rejected even when file hashes are unchanged or self-consistent.
