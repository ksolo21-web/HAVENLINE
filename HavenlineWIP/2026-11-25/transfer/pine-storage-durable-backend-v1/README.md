## Bounded persistence adapter
Own-only randomly generated /tmp path with dedicated prefix+marker, private owner-only directory/files, directory-relative no-follow/no-FIFO checks and an exclusive POSIX flock. Each newly booted fixture writer atomically claims a durable monotonic epoch. A pending old process keeps its prior epoch, exact primary SHA256 and decoded account; at transaction time it must reacquire the lock and prove all three still match, so a fresh process invalidates it even if the ledger is otherwise untouched. Stale same-epoch snapshots also fail exact identity before stage; wrong object, previous object or no live local capability denies without advancing state. One fixture-only deposit ID transports one wood, with no real receiver/world semantics. A trusted harness issue has no public receipt or amount import; this is not production command identity. Under the exact lock the stage is checked, flushed and fsynced, atomically replaced on the same directory, then directory-fsynced, and only then published in-session. Checksums are integrity checks, not authentication against hostile code/filesystem changes.
