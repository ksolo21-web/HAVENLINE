# Independent scoped review of paid pine + simulated storage ledger

Exact producer seal 392db89a… and prior paid pine source 2939ea7d… verified. Source comparison: the v1 ledger admits starter IDs and an immutable center-hearth debit of three wood; v2 adds paid pine occurrences, requires carried stock equal to occurrences once paid, and disallows a naïve deposit. Canonically emitted v1 and v2 map without losing any carried wood, receipt or original ordered collected IDs; stored wood and deposit high-water start at zero. The envelope hashes the exact payload string, including an unsorted fixture. Existing readers are not claimed to read v3.

Exact-model review: 729 independently enumerated mixed harvest/differently sized deposit traces (3420 successful steps). An independently retained list of deposit sizes proved carried + stored = paid harvests, and independent operation counts proved separate monotonic IDs. Receipt and starter order stay exact throughout. Conservation alone was insufficient: a separately created valid-checksum payload with two positive deposit transactions but only one stored unit was rejected. Before promotion of a two-unit deposit, cold reload retains [3,3,0,0]; after promotion before old live publication, reload sees [3,1,2,1], ordered harvest/carried/stored/deposit. An old ticket does not transfer to the new instance and a stale old writer after changed durable bytes cannot overwrite them.

Limit: calling cold_boot() alone is not fencing; an old process object still deliberately retained with a pending ticket can apply it before durable bytes change. Genuine simulated ColdStop retires that object, so the documented single-writer interruption test stands, not concurrent lifecycle guarantees. Checksum is not authentication, no real save or disk restart, and no game/world/receiver binding, storage rule, site, price or gameplay insertion.

Reproduce: python verify.py with the two pinned sibling packets. Only listed reviewer files are portable; no saves, original geometry, or remote.
