# Detached Level 1 five-second paid pine renewal
Baseline 11c14a1c41971067c7dc97db69375f720a408f68. The earlier source-only audit 99de60c2… (archived at f48f1c3…) explains why baseline never gives renewed wood. The chosen rule is exactly +1 wood on a completed repeat cut of the same existing pine, if its first accepted strike was after the unchanged three-wood hearth receipt. A cut begun before payment remains visual-only. No pickup/receiver/axe/touch/animation, assets, purchase cost or gate change is included.

## Authority and compatibility
The exact opt-in integrated scene alone can latch an occurrence for that same attached resource tree, actor and exact paid receipt. The initial rejected/out-of-reach or cooldown input does not latch it. The accepted final strike is recorded separately from the tree's last attempted-input sequence. A synchronous identity-checked settled event is consumable only while the same tree/actor are live, at exact ready-to-credit phase with all three accepted strikes and the current expected occurrence. Visual respawn and restoring the initial collected marker do not earn wood. No authority waits in queued event state across a restart.

The ledger stays exact payload v1 before the first renewed cut, keeping the original three starter IDs and untouched four-field receipt. Version 2 is a compact bounded monotonic counter (no growing array); v2 requires exact paid state and typed wooden count equal to committed occurrence count. Each valid settled event stages a cloned ledger and adds one and only one without repeating the hearth debit. Original application and v1 save-envelope checksum/profile/promotion implementation unchanged. Backward **read** compatibility for v1 in this candidate, not downgrade compatibility for original preview reading v2. The checksum validates accidental inconsistency; it is not an authentication claim for a malicious writer with filesystem access.

The integrated preview honors the existing opt-in marked disposable profile only when explicitly supplied. Without it, the authority remains ephemeral and does not read/write a save. Restore of a collected pine follows original restore_collected behavior: starts a fresh five-second hidden cycle, not durable replay of a settled event. A pre-promotion storage failure leaves live stock, exact old primary and receipt untouched, blocks further actions in that profile session, and cannot yield wood on restart.

## Reproduce
Only run `bash native.sh PATH_TO_EXACT_LOCAL_REPO` under a parent-approved functional lease. Runner checks seven exact commit blobs, reconstructs the archive into a fresh stage, applies the patch, acquires the serial Godot lock and isolates HOME/config/data/cache/runtime/TMP. Native disposable receiver tests create one fresh marked /tmp profile and never open a user save. The injected scene observer is test-only: it sends wrong source, wrong receipt, and wrong object to the live handoff before calling the exact original receiver; it does not bypass movement, cut or purchase. Raw temporary paths, imported caches, copied meshes and disposable save contents are excluded from the portable packet.

Total 172 assertions, five zero exit codes including import, no engine error diagnostics in the final corrected runs. The same bound pine disappeared and stood exactly at 299/300 ticks without an award from visibility. At first paid cut 0→1 wood and at second 1→2; interrupted next save leaves exactly the previous primary bytes and no stock change; restart recovers 2 at unchanged actor spawn/basis, then a genuinely new completed cut yields 3. The interrupted event was forced by an unopenable staging path, not a power-loss or hostile-filesystem simulation.

Exact source checkout stores the hearth in three parts. The runner materializes the concatenated commit blobs only, enforces known SHA-256 35d55290… for the generated GLB, and archives no new asset. The preliminary bare-archive import stopped on this baseline materialization dependency; the final runner verifies and materializes it before any Godot run.
