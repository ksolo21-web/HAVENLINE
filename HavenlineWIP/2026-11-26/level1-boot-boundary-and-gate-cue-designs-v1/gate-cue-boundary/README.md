# One future gate cue handoff boundary, not a publisher or player

Canonical first hearth has one authority path: fund_opening_receiver verifies exact installed/visible purchased scene view, real actor reach, unpaid ledger and typed wood; creates next ledger, applies pay_center_hearth and publishes via successful _commit_opening_progress (after commit only if an explicit authorized save exists). The integrated opening's normal scene is ephemeral. This is the first purchase domain, not a gate trigger. _commit_opening_progress is also called for wood and in detached paid-pine source, so its successful return alone is not a first-hearth or gate classification. sync_progress_visuals calls set_earned and initializes already-closed gates; a cold loader can produce precisely that closed state silently.

Gate motion instead comes from the indexed original gates iterated in step_technical_gates after actor motion and gate.advance. The exact V2 observer/authorized historical snapshots already establish transition discrimination; do not duplicate that math. For a future producer, pay receipt is only eligibility, never a trigger. Only after the registered scene-owned publisher classifies the completed physical edge from authentic gate, it proposes a one-way event using the typed fields in handoff.json. Phase/epoch origin is registered by local source ownership, not a caller-supplied JSON flag. Per-epoch order is issued on the source thread; the optional consumer does not re-evaluate geometry or read/modify gameplay/persistence, never attempts reuse across epochs, and cannot infer an event from UI/restore/initial enable. Reserve separate cue channel/namespace to avoid collision with purchase. Muted or missing cue is consumed/drop-only, not playback backlog. No listener or external API created here.

Compatibility verdict: no direct unmodified route through the known old test-only wood/first-hearth routing. Its documented acceptance is original v1 receipt events only and existing bus boundary does not authorize a verified gate signal; no exact standalone owned player source callable here. Names or an SFX bus do not make new publisher tags supported. A later separate admitted adapter may accept only this gate envelope locally and emit one inert intent, initially muted/unmapped. Independently confirm both publisher and consumer boundary types/code, fail-closed cold/replay/mute and no effect on prior wood/hearth, then only under T54 authority bind reviewed cue/audio. Existing South/East logs are mechanics only; old Dummy evidence never supports audibility.

No engine, audio creation/playback, scene, event or save implementation; T54 remains locked.
